# ArchSentinel Tech 

## 从一次作业提交到一份可解释的质量反馈

ArchSentinel 是面向代码类课程作业的 AI 评估与审查系统。学生提交代码仓库、说明文档和单元测试后，系统从代码规范、质量缺陷、模块设计、架构健康和版本演化等角度完成自动初评，标出问题所在的文件与代码行，并给出问题依据和修改建议。

系统服务于“AI 初评纠错、教师高阶终审”的双轨评价流程。自动化分析负责处理规则明确、重复度高的基础检查，教师则重点判断需求理解、设计取舍、工程实践和创新性。这样既缩短反馈周期，也保留课程评价中不可替代的专业判断。

## 评审流程

1. **提交作业**：导入原始版本与最终版本项目，形成可比较的项目快照。
2. **结构解析**：提取包、类、方法、变量及其调用、继承和访问关系，建立项目依赖图谱。
3. **质量检查**：按照代码规则和架构规则检测问题，并定位到文件、行号和相关实体。
4. **智能解释**：结合知识库解释问题成因、违反的设计原则、可能影响和常见改法。
5. **生成报告**：汇总代码质量、架构反模式和演化数据，形成评分、依据与改进建议，供学生修改和教师终审。

## 核心能力

| 模块 | 中文名称 | 主要作用 |
| --- | --- | --- |
| ArchMapper | 架构测绘仪 | 提取实体和依赖关系，展示项目结构与多层次依赖图谱 |
| ArchInspector | 架构巡检仪 | 检查代码规范、缺陷、安全风险和异常处理问题 |
| ArchCompass | 架构指南针 | 识别通用反模式，并支持面向课程要求的自定义架构约束 |
| ArchVitals | 架构体征仪 | 对比版本度量、实体归属、耦合面、重构和侵入式修改 |
| ArchBrain | 架构智核 | 连接规则、知识库和 AI 推理，生成可理解的分析说明 |
| ArchNurse | 架构护理师 | 根据检测证据组织修改优先级和重构建议 |
| ArchDiagnose | 智能诊断台 | 汇总各模块结果，形成综合评分和可导出的反馈报告 |

## 已实现的分析范围

- 代码质量检查覆盖 OOP、Serialization、Security 等 9 大类共 88 条规则。
- 通用反模式包括接口未解耦、循环依赖、循环继承、数据泥团、特性依恋、多重路径继承和霰弹式修改。
- 自定义架构检查支持将自然语言约束转换为可执行的规则描述；既有项目材料记录了 6 类共 24 种架构违约检测。
- 版本分析覆盖传播成本、解耦水平、内聚、封装、继承和多态等指标，并提供重构与侵入式修改对比。

## 对学生和教师的价值

对学生而言，系统反馈不止于“扣了多少分”，而是回答三个问题：问题在哪里、为什么构成问题、接下来怎样修改。学生可以从依赖图和版本曲线理解局部代码对整体结构的影响，并通过知识库补充相关概念。

对教师而言，系统提供统一的初评口径和可追溯证据。教师可以快速查看高优先级缺陷、架构风险和版本变化，把更多时间投入到设计合理性与工程能力评价。最终评价仍由教师完成，AI 结果作为辅助证据，而非替代教师判断。
