# ArchInspector 
## 架构巡检仪

ArchInspector 面向代码层完成自动巡检，识别编码缺陷、不一致行为、安全风险和可维护性问题。系统不仅汇总问题数量，还保留规则说明、优先级、文件路径、行号和代码片段，使每一项评价都可以追溯。

## 规则范围

既有项目材料记录了 OOP、Serialization、Security 等 9 大类共 88 条规则。检查内容包括异常处理、资源释放、线程安全、命名与可见性、序列化使用、安全 API 和常见复杂度问题。规则采用可配置方式组织，便于根据课程规范扩展检查口径。

## 检测流程

1. 解析源代码的抽象语法结构与实体依赖。
2. 按规则统计节点属性和关系特征。
3. 对符合违规条件的节点生成问题记录。
4. 按规则类型和优先级汇总，并关联到原始代码位置。
5. 将结果交给综合评估模块生成解释和修改建议。

## 页面展示

页面左侧使用图表展示不同优先级和规则类型的数量，右侧列出规则名称、说明、优先级与问题条数。点击“查看详情”后，可以继续查看具体文件和行号，再打开对应代码片段。

这种“统计概览—规则明细—代码证据”的三级结构，既适合教师快速浏览，也方便学生逐项修复。录制视频时，应至少完整演示一次从规则表下钻到代码片段的过程。

## 教学价值

ArchInspector 将基础代码审查前置到作业提交之后。学生可以优先处理高风险问题，再逐步改进中低优先级问题；教师则可以把统一规则作为形成性评价依据。相比只给出“代码规范较差”的评价，精确到文件和行号的反馈更容易转化为实际修改。

## 与 AI 评估的关系

规则检测负责提供确定、可复核的事实，AI 负责把多条事实组织成自然语言说明。系统先有检测证据，再生成评价，避免仅凭语言模型主观判断代码质量。最终报告会说明总体情况、主要问题和改进建议，但教师仍可结合课程目标调整结论。
