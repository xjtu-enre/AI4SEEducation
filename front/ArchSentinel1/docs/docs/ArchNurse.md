# ArchNurse 
## 架构护理师

ArchNurse 面向检测后的改进阶段，把分散在不同模块中的问题转化为有顺序的治理建议。它强调先处理高风险且影响明确的问题，再逐步改善模块结构，并通过后续版本重新检测改进效果。

## 建议组织方式

- **立即修复**：资源未关闭、异常处理不当、线程安全和高风险安全问题。
- **结构改进**：高耦合、低内聚、职责过多、接口与实现未解耦等设计问题。
- **演化治理**：侵入式修改、接口契约不稳定和版本兼容风险。
- **持续观察**：传播成本、封装、继承和多态等指标的长期变化。

## 常见改进方向

系统会根据问题类型推荐提取方法、移动职责、引入参数对象、清理继承关系、增加稳定扩展点、减少直接字段访问等重构思路。建议会说明对应的检测依据，便于学生理解为什么需要修改，而不是直接给出无法解释的代码替换。

## 改进闭环

1. 从综合报告选择高优先级问题。
2. 查看规则说明、代码位置和关联依赖。
3. 根据建议完成修改并补充单元测试。
4. 提交新版本，再次运行质量与架构检查。
5. 对比问题数量和版本指标，确认修改是否真正改善项目。

## 教学价值

ArchNurse 把“发现问题”延伸到“验证改进”。学生需要根据证据完成修改，并用新一轮检测证明改动效果。教师可以据此评价学生的分析能力、重构能力和质量意识，而不仅是最终程序是否运行。

## 与 ArchDiagnose 的关系

ArchDiagnose 负责汇总现状和给出综合评价，ArchNurse 更关注后续行动与优先级。两者共同形成“检测—解释—修改—复查”的闭环。系统提供建议，但不会替代学生完成设计取舍，也不会自动覆盖学生代码。
