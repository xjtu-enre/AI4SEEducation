# ArchVitals 
## 架构体征仪

ArchVitals 从版本演化角度观察项目健康状态。单次扫描只能说明当前有哪些问题，多个版本的连续数据则能够回答结构是在改善还是恶化，以及一次修改是否带来了新的耦合和兼容风险。

## 五类分析视角

### 度量结果

通过传播成本、解耦水平、内聚、封装、继承和多态等指标绘制版本曲线。学生可以观察指标变化发生在哪个版本，并结合提交记录分析原因。

### 耦合面分析

耦合面描述下游新增实体与上游复用实体之间的依赖关系。系统区分不同来源和扩展方式，帮助判断项目是通过稳定接口扩展，还是直接依赖内部实现。

### 实体归属

系统分析实体来自上游、下游还是共享扩展，呈现不同归属类型的数量和分布。该视角有助于识别重复建模、复用不足和上下游边界不清等问题。

### 重构检测

系统识别提取方法、移动方法、重命名、参数调整等重构行为，并展示修改前后的代码。教师可以区分有目的的结构优化与只为通过测试进行的局部修补。

### 侵入式修改

当下游直接修改上游字段、方法签名、调用关系或可见性时，系统记录修改类型并提供上下游代码对比。这类改动容易在后续升级中产生冲突，是版本兼容性评估的重要依据。

## 核心方法

ArchVitals 结合实体归属、依赖关系、上下文结构和重构语义，对两个版本中的实体进行匹配。既有项目研究中，实体归属检测准确率达到 90% 以上，并与 CodeShovel、CodeTracker 等工具进行了对比验证。

## 教学价值

版本曲线让课程评价从一次性结果转向过程性证据。学生可以看到某次提交如何改变传播成本、内聚或封装；教师可以判断修改是否真正改善了结构。对于团队项目，耦合面和实体归属还可以帮助分析模块责任与协作边界。
