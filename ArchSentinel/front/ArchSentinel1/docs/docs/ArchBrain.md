# ArchBrain 
## 架构智核

ArchBrain 是连接检测结果、知识库和 AI 解释能力的知识中枢。静态分析模块负责回答“检测到了什么”，ArchBrain 进一步组织规则定义、设计原则和项目上下文，帮助学生理解“为什么这是问题，以及应当从哪里开始修改”。

## 知识组成

- 代码质量规则的含义、优先级和典型风险。
- 架构反模式的定义、识别条件和违反的设计原则。
- 常见重构方法及其适用场景。
- 代码度量指标的解释，以及指标变化可能反映的结构问题。
- 来自各分析模块的项目事实，包括问题数量、代码位置和版本变化。

## 智能解释流程

1. ArchMapper、ArchInspector、ArchCompass 和 ArchVitals 生成结构化检测结果。
2. 系统从知识库中检索与问题类型相关的概念和修改依据。
3. AI 根据检测事实组织评分依据、总体情况、现存问题和改进建议。
4. 输出内容保留原始规则、文件位置和图表，供学生与教师复核。

## 辅助查询

学生可以围绕检测结果查询概念，例如“什么是特性依恋”“循环依赖为什么影响测试”“怎样降低霰弹式修改风险”。知识库提供稳定的基础说明，AI 则结合当前项目给出更有针对性的解释。

## 使用边界

ArchBrain 的作用是辅助理解和决策，不替代教师评价。评分与建议必须建立在可追溯的检测数据上；涉及需求取舍、业务合理性和创新性的判断，仍由教师结合课程目标完成。对于 AI 生成内容，教师和学生都可以返回原始问题位置进行核对。

## 教学价值

把知识条目与学生自己的代码问题连接起来，可以缩短从“看到术语”到“理解并修改”的距离。学生得到的不再是一段与项目无关的通用答案，而是带有规则依据和代码上下文的学习反馈。
